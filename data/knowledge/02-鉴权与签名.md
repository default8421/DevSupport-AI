# 鉴权与签名

## 鉴权方式

平台采用 API Key + 请求签名的鉴权方式。每个请求必须携带三个鉴权要素：

- `X-Api-Key`：应用的 API Key，标识调用方。
- `X-Timestamp`：请求发起时的秒级时间戳，用于防重放。
- `X-Sign`：请求签名，基于 Secret Key 计算。

## 签名算法

签名生成步骤如下：

1. 收集所有业务参数（不含签名本身）以及 `X-Api-Key`、`X-Timestamp`。
2. 将参数按参数名字典序（ASCII 升序）排序。
3. 拼接为 `key1=value1&key2=value2&...` 的字符串。
4. 在末尾追加 `&secret=你的SecretKey`。
5. 对拼接字符串做 HMAC-SHA256 计算，得到的十六进制小写字符串即为 `X-Sign`。

示例（伪代码）：

```
raw = "api_key=ak_live_xxx&idcard=110...&name=张三&timestamp=1718000000"
sign = hmac_sha256(raw + "&secret=" + secret_key)
```

## 401 鉴权失败常见原因

返回 HTTP 401 时，请按以下顺序排查：

- **API Key 已过期（AUTH_KEY_EXPIRED）**：登录控制台查看 Key 的过期时间，重新生成后更新服务端配置。
- **API Key 无效（AUTH_KEY_INVALID）**：Key 复制不完整或已被禁用。
- **签名错误（SIGN_INVALID）**：最常见。检查参数排序是否为字典序、是否使用了正确的 Secret Key、时间戳是否在服务器允许的 5 分钟窗口内。

## 签名错误（SIGN_INVALID）排查要点

1. 确认参数排序严格按字典序，且未遗漏或多加参数。
2. 确认 Secret Key 与当前 API Key 配对，且未使用测试环境密钥调用生产。
3. 确认时间戳为秒级、与服务器时间偏差不超过 5 分钟（注意时区与 NTP 同步）。
4. 确认拼接字符串编码为 UTF-8，未对 value 做额外的 URL 编码导致不一致。

## 安全建议

Secret Key 不得硬编码在前端或客户端代码中，不得提交到代码仓库。一旦泄露，请立即在控制台重置。
