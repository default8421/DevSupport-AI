# 文档上传 + 知识库租户隔离 实现计划

**Goal:** 先给知识库补上租户隔离（三条泄漏路径全堵），再在此之上开放用户自定义文档上传（md/txt/pdf，后台异步处理）。

**Architecture:** 单 Milvus collection 加 `tenant_id`/`doc_id`/`source` 三个标量字段，内置文档 `tenant_id=""` 表示全局；检索时过滤 `tenant_id in ["", 本租户]`。BM25 语料携带租户并在取 top-k 前掩码。上传走 FastAPI `BackgroundTasks`，状态机落在已有的 `knowledge_document.status` 列上。

**Tech Stack:** Python 3.11 / FastAPI / Milvus (pymilvus) / SQLAlchemy 2.x async / rank_bm25 / pypdf / pytest + pytest-asyncio

设计依据：`docs/specs/2026-09-04-文档上传与知识库租户隔离-design.md`

## Global Constraints

- **执行环境**：后端命令必须走 `backend/.venv/bin/python`（等价 `make test` / `make lint`）。
  本机系统 python 是 3.9，用裸 `python` 会在 `str | None` 语法上直接失败。
- **新增依赖只有 `pypdf`**（已验证纯 Python wheel）。不引入 `unstructured`、`langchain-community`
  这类重型文档加载器。
- **`tenant_id` 在检索链路上是必填关键字参数，一律不给默认值。** 给默认值会让漏传变成
  静默的行为差异；必填则漏传直接 `TypeError`，测试里就暴露。
- **全局文档用空串 `""` 标记，不用 `"global"`。** 让"忘记传租户"失败到安全侧：
  过滤退化成只匹配全局文档，而不是匹配全部。
- **过滤表达式只在 `store.py` 内部拼装。** 不让调用方自己传 `expr` 字符串——
  每个调用点自己拼就意味着每个调用点都可能忘记租户条件。
- 租户/用户身份只来自 JWT 解出的 `CurrentUser` 或 `ToolContext`，**绝不**取自请求体、
  文件内容或模型输出。
- 上传文件落 `data/uploads/{tenant_id}/{doc_id}{ext}`，**绝不落 `data/knowledge/`**
  （那里的 `*.md` 会被 `ingest` 当作全局文档摄取，当场废掉隔离）。
- 存储路径**只用生成的 `doc_id`**，绝不使用用户提供的文件名。
- 上传文本在切分前必须过 `guardrail.desensitize.desensitize_text()`——
  用户文档里很常见他们自己的 API Key。
- 不引入数据库迁移工具；新增列的 `ALTER TABLE` 写进 `scripts/`，不靠 `create_all`
  （它对已存在的表不补列）。
- 代码注释与文档字符串用中文；`ruff` line-length = 100。
- 每个 Task 结束提交一次，提交前必须 `make test` 全绿 + `app/` 下无新增 ruff 告警。

- [ ] **Step 2: 实现 `build_filter`**

```python
def _q(value: str) -> str:
    """转义进过滤表达式的字符串字面量。"""
    return value.replace("\\", "\\\\").replace('"', '\\"')


def build_filter(*, tenant_id: str, error_code: str | None = None) -> str:
    """拼装 Milvus 过滤表达式。全局文档 tenant_id 为空串，恒可见。

    用 in 而不是 a == x or a == y：避免与后续 and 的运算符优先级问题——
    拼成 A or B and C 少一层括号就是错的。
    """
    scopes = [""] if not tenant_id else ["", tenant_id]
    parts = ['tenant_id in [%s]' % ", ".join(f'"{_q(s)}"' for s in scopes)]
    if error_code:
        parts.append(f'error_code == "{_q(error_code)}"')
    return " and ".join(parts)
```

- [ ] **Step 2: 语料携带租户并加时间戳**

模块级状态从 `_bm25` / `_corpus` 扩展为再加一个 `_built_at: float`。
`_ensure_bm25()` 的重建条件：`_bm25 is None or time.monotonic() - _built_at > ttl`。

TTL 的作用是给多 worker 部署兜底：BM25 是进程内状态，worker A 处理的上传，
worker B 的索引不会知道。TTL 让陈旧自愈，代价是最坏情况下新文档 60 秒后可见。

- [ ] **Step 3: 掩码后再取 top-k**

```python
scores = _bm25.get_scores(_tokenize(query))
# 先按租户把不可见条目置为负无穷，再取 top-k。
# 顺序很关键：先取 top-k 再过滤会白白损失召回——
# 本租户的片段可能被其他租户的高分片段挤出候选。
visible = ("", tenant_id) if tenant_id else ("",)
masked = [
    s if _corpus[i].get("tenant_id", "") in visible else float("-inf")
    for i, s in enumerate(scores)
]
top_idx = sorted(range(len(masked)), key=lambda i: masked[i], reverse=True)[:top_k_each]
bm25_hits = [_corpus[i] for i in top_idx if masked[i] > 0]
```

- [ ] **Step 4: 去重 key 加租户**

`vec_order` / `bm25_order` 里的 id 同步改成这个二元组，RRF 的 `scores` dict key 类型随之变化。
